# QAC v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a provider-neutral, deterministic Go library that allocates work between constrained cognitive resources.

**Architecture:** The root `qac` package owns immutable domain data, validation, and the policy contract. `policy/threshold` owns one immutable weighted policy, including eligibility, hierarchy transitions, score factors, and deterministic reasons. The module has no runtime dependencies and no Ghost imports.

**Tech Stack:** Go 1.26.5, standard library, Jujutsu, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-11-qac-v01-design.md`

## Global Constraints

- Module path is `github.com/haha-systems/qac`.
- Use Apache-2.0 and no runtime dependencies.
- Do not invoke models, perform I/O, parse configuration, mutate budgets, log, network, or import provider or Ghost packages.
- Decisions are deterministic and policy instances are safe for concurrent use.
- Commit every task with a Conventional Commit message using `jj`.

```go
type Resource struct { ID string; Capability, Cost, Scarcity float64; Available bool; Metadata map[string]string }
type Context struct { CurrentResource string; Uncertainty, Importance, Novelty, ExpectedGain float64; FailedAttempts int; Metadata map[string]string }
type ResourceBudget struct { Enabled bool; RemainingInvocations *int; Cooldown bool }
type BudgetState struct { Resources map[string]ResourceBudget }
type Request struct { Context Context; Resources []Resource; Budget BudgetState }
type Action string
const ( ActionContinue Action = "continue"; ActionEscalate Action = "escalate"; ActionRelease Action = "release"; ActionStop Action = "stop" )
type Factor struct { Name string; Value, Weight, Contribution float64 }
type Eligibility struct { ResourceID string; Eligible bool; Reasons []string }
type Decision struct { Action Action; From, To string; Score, Threshold float64; Factors []Factor; Reason string; Eligibility []Eligibility }
type Policy interface { Decide(context.Context, Request) (Decision, error) }
```

`ValidateRequest` must reject empty input, empty or duplicate IDs, non-finite or out-of-range normalized resource and signal values, negative failures, an absent current resource, and budgets for unknown resources. It must not mutate its argument.

- [ ] **Step 3: Implement deterministic transition selection**

Compute normalized failures as `min(float64(FailedAttempts)/float64(FailureSaturation), 1)`. Build five positive factors for pressure. For a candidate destination, append `cost` and `scarcity` negative factors whose contributions are `-weight * resourceValue * (1-ExpectedGain)`. Sum factors without clamping.

Evaluate the adjacent upward transition first when score meets its escalation threshold. Otherwise, evaluate the adjacent lower transition when score is below its release threshold. Return `continue` when neither applies or the applicable destination is ineligible. Generate a deterministic reason from action, source, destination, score, threshold, and the three largest absolute factor contributions, breaking ties by factor name.
