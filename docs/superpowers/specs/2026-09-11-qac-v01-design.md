# QAC v0.1 design

## Summary

QAC is a dependency-free Go module at `github.com/haha-systems/qac`. It makes
deterministic, inspectable allocation decisions across arbitrary cognitive
resources. It does not invoke resources, read configuration, mutate budgets,
perform I/O, or contain provider or workflow concepts.

## Public API

The root package exports `Resource`, `Context`, `Request`, `BudgetState`,
`ResourceBudget`, `Action`, `Decision`, `Factor`, `Eligibility`, and `Policy`.
`Policy.Decide(context.Context, Request) (Decision, error)` is the only policy
contract. Resources and context retain opaque string metadata, which the built
in policy ignores.

`Decision` contains action, source, destination, score, threshold, factors,
reason, and eligibility for every requested resource. Scores may be negative;
factors always sum to the reported score. `ActionStop` has an empty destination.

## Threshold policy

`policy/threshold` provides an immutable, concurrent-safe weighted threshold
policy. Its configuration contains an explicit hierarchy, transition thresholds,
weights, failure saturation, and `OnCurrentIneligible`.

Default weights are uncertainty `.25`, importance `.15`, novelty `.10`,
expected gain `.35`, failures `.15`, cost `.20`, and scarcity `.30`.
Failure saturation defaults to three. Default adjacent thresholds are `.55` and
`.80` for escalation and `.25` and `.45` for release.

For a candidate destination, the score is:

`pressure - (costWeight*cost + scarcityWeight*scarcity) * (1-expectedGain)`

where pressure is the weighted sum of the five context signals. The destination
cost and scarcity terms are negative factors. This retains scarce cognition when
expected gain is low while allowing high-value escalation.

The policy evaluates constraints before transitions. A resource is ineligible
when unavailable, omitted from the hierarchy, disabled, cooling down, or has an
exhausted invocation budget. Normal moves are adjacent hierarchy transitions.
An unavailable destination cannot be selected. If no resource is eligible, the
policy returns `stop` with evidence.

`OnCurrentIneligible` defaults to `stop`. `nearest_eligible` selects the nearest
eligible hierarchy resource, preferring the lower resource on a tie.
`least_cost_eligible` orders candidates by cost, scarcity, then hierarchy index.
This rule runs before normal scoring. A selected higher resource produces
`escalate`; a lower resource produces `release`.

## Validation and errors

Requests reject empty or duplicate resource IDs, an unknown current resource,
non-finite or out-of-range normalized signals and resource values, negative
failed attempts, and malformed budgets. Threshold configuration rejects empty
or duplicate hierarchy IDs, hierarchy IDs absent from a request, invalid
weights, thresholds outside `[0,1]`, and non-positive failure saturation.

## Delivery

The repository uses Go 1.26.5, Apache-2.0, and no runtime dependencies. It
contains threshold-policy behaviour and validation tests, a small tier example,
a README, and GitHub Actions for tests, vet, and build. A narrow fuzz test checks
that valid inputs never select ineligible resources and never produce non-finite
scores. Ghost integration is explicitly out of scope.
